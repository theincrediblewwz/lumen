# Lumen 0.1.14：长文、导入方式与恢复

## 两种导入方式

在“从对话新建白板”或“向白板添加一棵树”中选择来源，再选择模式：

- **AI 重构图谱**按主题生成新的问题树。长文各批结果在本机共同根下合并，跨批主题可能重复，请在预览中核对。
- **忠实逐轮图谱**保留每次 AI 回答，每条已选回答对应一个节点。新 AI 只补充概括标题、简短导读和建议层级；原回答从本地来源直接附入文档，不能在预览中改写。层级说明是新 AI 的建议，不代表原对话已有树结构。

分享链接可按轮次选择。Markdown 支持明确的“提问 / 回答”角色标题和“第 N 条回答”编号标题；代码围栏中的相似标题不会分割回答。无法识别明确回答边界时，忠实模式给出提示，不把普通文章擅自拆成多轮。一个轮次中的多条 AI 回答各自保留；只有提问的轮次不生成空回答文档。

长回答会按顺序完整读完片段，再将导读组合为同一节点；原回答的 CRLF、公式、空格和尾空行保留。原回答与 AI 生成导读分开校验：来源最多32MiB，导读仍受单节点64KiB、全树2MiB限制，超限会拒绝，不静默裁剪。

## 长文与临时服务满载

每次请求受当前上下文预算及12,000估算输入 tokens 上限共同约束，提示词和 JSON 开销也计入。应用按段落/行优先切片，逐批处理，显示批次、覆盖字符数与取消入口；不会把用户未选择的轮次发送给模型。全部批次成功后才产生可确认写入的方案；失败、超时或取消不会写入部分白板。合并在本机完成，不追加一次全文模型总结请求。

`HTTP 429` 中的 `ttft_admission_refused / cell is at capacity` 表示上游暂时无法接纳请求，不能单凭此判断文档无效或账户余额不足。临时满载/限流在响应流开始前最多自动重试三次，遵守服务端等待提示，每次等待最多60秒且可取消；更长等待返回提示。真实额度不足、认证错误，以及已经开始输出后中断的响应不会自动重播。

## 预览、保存与升级

1. 先核对来源、已选轮次和模式，点击“分析并预览”。
2. 检查标题、AI 导读和建议关系。忠实模式可以展开只读原回答；每个原回答与来源精确对应。
3. 明确确认后才创建或写入白板。完整原文与选择依据另行保留，现有原生事务仍负责冲突核验、备份与原子写入。

升级前保留当前应用包与资料备份。本次没有迁移资料目录、API Key 或模型连接。回滚应用时可重装原版本包；资料恢复使用应用现有的白板备份或资料包入口。项目/全库资料包应恢复到**新目录**后核对，再决定打开副本；它不覆盖旧资料库，也不携带连接密钥和本机 AI 授权。桌面新增的项目/全库资料包不宣称可由 Android 恢复；原有共享单板格式另按兼容规则使用。
